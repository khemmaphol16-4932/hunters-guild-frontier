# Category 11 — Animations

**Status:** PROPOSED, 2026-09-12
**Requires:** `art/ART_BIBLE.md` §10, `art/specs/02-hunter-characters.md`, `art/specs/03-monsters.md`
**Scope:** The state machines and timing rules every animated asset follows. Frames themselves live
with their subject; this file owns *behaviour*.
**Output style:** Sidecar JSON per sheet + rules

---

## 0. Two problems this file solves

**Problem 1 — speed.** The world runs at 1×, 2× or 4× (DL-065) and combat honours the current
speed. A walk cycle played at a fixed 12 fps while the hunter moves 4× faster makes the feet skate
across the ground. An attack played at 12 fps can outlast a 4×-speed attack cooldown.

> **Rule A-1.** Locomotion frames (`walk`, `run`, `carry`, `injured_walk`) advance by **distance
> travelled**, not by time: one full cycle per 2 tiles. Feet stay planted at every speed.
>
> **Rule A-2.** Action frames (`attack`, `cast`, `windup_*`, `hit`, `heal`, `gather`, `sell`)
> play at **12 × speed** fps, capped at 48. They always finish inside the action they depict.
>
> **Rule A-3.** Ambient loops (`idle`, `work`, `rest`, building smoke) stay at 12 fps. The town
> looks busier at 4× because more *happens*, not because every chimney flickers faster.

**Problem 2 — cost.** Thirteen town jobs in `town/jobs.json`, three skeletons, four facings. Authoring
a `work` loop per job per skeleton is ~80 sheets. Most jobs share a motion.

> **Rule A-4.** Jobs map to **six work motions**, authored once per skeleton.

| Motion | Frames | Jobs (`town/jobs.json`) |
|---|---|---|
| `work_hammer` | 8 | `forge_work`, `leatherwork` |
| `work_chop` | 8 | `timber_cutting`, `quarrying` (tool layer swaps axe ↔ pick) |
| `work_stir` | 8 | `field_kitchen` |
| `work_write` | 8 | `archive_work` |
| `work_tend` | 8 | `infirmary_rounds` |
| `work_watch` | 8 | `gate_watch`, `wall_patrol`, `field_survey` (idle variant, head turns) |
| *(reuse `attack`)* | — | `hunter_drill` — sparring at the Drill Yard |
| *(reuse `walk`)* | — | `escort_duty` |
| *(real combat)* | — | `town_hunting` — the actual combat system (`REQ-TWN-007`) |

13 jobs → **6 motions × 3 skeletons = 18 loops.** The tool in the hand is a paper-doll layer, so
`work_chop` with an axe and with a pick is one animation.

## 1. Hunter state machine

```
            ┌──────── work_* ◄──── assigned job (TownJobs)
            │            │
   idle ◄───┼──── rest ◄─┤ fatigue high / at housing
    │ ▲     │            │
    ▼ │     ▼            ▼
   walk ──► gather ─► (loot to pack)          sell ◄── at market, carrying loot
    │                                           │
    ▼                                           ▼
  attack / cast ◄─► hit                        idle
    │
    ▼  HP 0
  downed ──► (rescue) ──► carry / injured_walk ──► infirmary: rest
    │
    ▼  Black zone, not rescued
  death
```

| Transition | Blend | Notes |
|---|---|---|
| Any → `hit` | Cut | Returns to the previous state |
| `walk` ↔ `idle` | Cut on a contact frame | Walk frames 01 and 05 are contact frames |
| Any → `downed` | Cut | `REQ-CBT-012`: a downed hunter cannot act — no state leaves `downed` except rescue or death |
| `downed` → `death` | 6-frame play | Black zone only (`REQ-ZON-001`) |
| Retreat (`REQ-CW-010`) | `run` | Fights only when physically blocked — `run` → `attack` only on a block |

**`reducedMotion`** — every loop holds on frame 01; actions show their key frame (impact, release)
for the action's duration. `ART_BIBLE.md` §12.4 already requires frame 01 of every loop to be a
valid standalone pose; this is where that pays off.

## 2. Sidecar JSON

Every sheet ships one. The renderer reads nothing from filenames except the sheet path.

```jsonc
// hunter_vanguard_skel_walk_se.json
{
  "frameWidth": 128,          // @2x
  "frameHeight": 160,
  "frames": 8,
  "pivot": [64, 144],         // @2x — bottom-centre of the ground footprint
  "loop": true,
  "advance": "distance",      // "distance" | "action" | "ambient"  (rules A-1 to A-3)
  "tilesPerCycle": 2,         // distance sheets only
  "contactFrames": [1, 5],    // safe cut points
  "keyFrame": null,           // action sheets: impact / release frame, used by reducedMotion
  "weaponBehind": false,      // per facing (specs/02 §3)
  "mirrorOf": null            // "se" if this facing is generated by mirroring
}
```

Action sheets set `"advance": "action"` and `"keyFrame": 3` (impact) or `4` (release). Telegraph
sheets add `"holdFrame": 3` — frame 03 holds for the skill's `telegraphSeconds` from
`monsters.json`, never a number written here.

## 3. Master state matrix

| Subject | Tier A (P0) | Tier B (P1) | Tier C (P2) |
|---|---|---|---|
| Hunter skeletons ×3 | `idle` `walk` `attack`/`cast` `hit` `downed` | `gather` `rest` `run` `work_*`×6 | `death` `rescue` `carry` `injured_walk` `sell` `celebrate` |
| Trash monsters | `idle` `walk` `attack` `hit` `death` | skill casts | — |
| Elites | Tier A + `windup_*` for telegraphed skills | `heal` | — |
| Bosses | Tier A + all `windup_*`/`cast_*` | phase overlays | — |
| Buildings | — | smoke, forge glow, banner, water (`ANM` kit parts) | construction dust |
| Props | lanterns, firepit | brazier | — |

**Frame budget per hunter skeleton:** Tier A 23 frames × 2 facings = 46 (92 for `ranger`); Tier B
adds 6 + 4 + 8 + 6 × 8 = 66 × 2; Tier C adds 6 + 6 + 8 + 8 + 4 + 6 = 38 × 2.

## 4. Acceptance — every animated sheet

- [ ] Sidecar JSON present and valid against the schema above
- [ ] Locomotion: no foot skate at 1×, 2× and 4× (rule A-1)
- [ ] Actions complete inside the shortest cooldown they can play under at 4× (rule A-2)
- [ ] Loops seamless: last frame → frame 01 with no pop
- [ ] Frame 01 of every loop is a valid standalone pose
- [ ] Contact frames declared and correct
- [ ] Reviewed in the world, at speed 1×, 2× and 4×, at zoom 0.55 and 1.8
